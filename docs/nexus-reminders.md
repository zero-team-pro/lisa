# Nexus reminders

A private authenticated Nexus owner can create one-time reminders using the existing `/tasks/v1` bearer token. `POST /tasks/v1/reminders` accepts an idempotent UUID `id`, `text` (up to 1000 characters), and `dueAt` (ISO 8601 with explicit offset). For a Telegram task, include `taskId`, `attempt`, and `leaseToken`; the server verifies the active task lease, saves the originating message ID and queues a 👍 reaction after committing. Repeating an identical ID returns the saved reminder. `GET /tasks/v1/reminders` lists the owner's pending, sending and uncertain reminders; `POST /tasks/v1/reminders/:id/cancel` cancels only a pending reminder.

The gateway checks for due reminders every five seconds and delivers through the Telegram bridge. Reminders are in PostgreSQL and do not require the Nexus Mac to stay online after creation. A send interrupted by a crash or a bridge timeout is marked uncertain rather than blindly repeated; delivery is not exactly once. Review uncertain rows operationally. Owner authorization is rechecked before any send. Telegram reaction failure is recorded without turning creation into failure.

Nexus worker support must be deployed after migration 9 and the server API. It resolves natural-language requests with the existing `lisa_task` profile and sends a validated reminder to the server before the task result callback. Reminder task completions are silent; errors and clarifications use the ordinary task response path. Roll back the worker before rolling back the API; do not remove migration 9 while reminders or compatible workers still need it.
